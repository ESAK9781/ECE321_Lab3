  Scoring (CS_Amp.py, util.py)

  6. Hard specs are scored as soft penalties. Each spec is 1 of 13 equally
     weighted terms, so the optimizer can trade a spec violation for gains
     elsewhere. Five of the 13 terms are resistor power, which is trivially
     satisfied.
  7. score_range returns 1 anywhere inside the range. The target only matters
     when you're outside the range. Once a design meets spec there's no reward

  Remaining issues

  1. The distortion term now drives designs onto the saturation edge
  (CS_Amp.py:263)
  To raise gm·RS1, the optimizer raises ID, which raises gm. The only thing that
  stops it is the saturation check, so designs stop where VDS = Vov. In the lab
  those designs will distort at almost any signal level, which is the opposite
  of what the term is for.
  - Fix the swing check (issue 2) first. With a real headroom limit, this term
    will push toward a sensible operating point instead of the triode edge.
  - For a better distortion estimate, use the gate-source signal relative to
    Vov. The required input is roughly 1.6 V / |Av|, it's divided down by (1 +
    gm·RS1), and HD2 ≈ v̂gs / (4·Vov). That accounts for both degeneration and
    Vov.

  2. Spec 13 (3.2 Vpp output swing) still isn't checked
  The only DC check is VDS > Vov, which allows zero room for a signal.
  - Require downward headroom: VDS − Vov larger than the 1.6 V peak swing plus a
    margin. RS1 is unbypassed, so the source moves with the signal too; account
    for that or add extra margin.
  - Require upward headroom: the drain current can't go below zero, so ID·(RD ∥
    RL) must exceed the peak swing.
  - Treat both as hard requirements, the way you now gate on saturation.

  3. Selection bug in the parent loop (optimizer.py:62–67)
  When a new candidate beats #1, the j = 1 iteration then also replaces #2 with
  the same candidate. You lose the old best and end up breeding a design with
  itself.
  - Stop after inserting the candidate, and shift both the solution and its
    score down together.
  - Separately, the first two candidates' scores are computed twice (lines
    56–57), which wastes time.

  4. Cutoff designs are still only partly rejected (CS_Amp.py:245–248)
  - The negative-product case still slips through. Your > 1 check only catches
    products larger than 1. Two negative factors like −0.5 × −0.5 = +0.25 still
    survive.

    that factor. In a random search of 200,000 designs, cutoff designs scored as
    high as 0.475.
  - The distortion term has a blow-up point. In cutoff, gm is negative. If
    gm·RS1 comes out near −1, 1/(1 + gm·RS1) blows up. Just past −1 the term
    becomes a huge positive reward, large enough to outweigh everything else.
  - Fix: have analyzeCSAmpModel return None (invalid) whenever Vov ≤ 0. That
    covers all three cases.

  5. Annealing is now too fast (main.py:9, anneal rate 0.75)

  hits the 1-index floor. VDD stops changing at about the same point, so the
  remaining ~87 epochs barely change anything. That's why seed 3 got stuck
  failing the gain spec.
  - Use a slower rate (about 0.05–0.1 over 100 epochs).
  - Or set a minimum step size, or add a restart when the score stops improving
    for a while.
  - Start with a smaller first step so early generations don't pile up at the
    clamped ends of the resistor list.

  6. Too little diversity: only two parents
  Combined with issue 3, the population often comes from a single parent.
  - Keep a larger pool of top designs (say 10–20), or use tournament selection.
